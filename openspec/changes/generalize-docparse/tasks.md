# Tasks

The implementer tier follows the model-routing skill:
- **[Opus]:** hard or ambiguous work: cross-module, design decisions left.
- **[Sonnet]:** fully specified, pattern-following work with concrete files and functions.
- **[Human]:** needs a person: labelling, licence decisions, data collection, or H100 access.

Ordering rule: every class's eval list is frozen (group 4) before any task that tunes docparse on that class (groups 5–7). Groups 1–2 land before `add-docparse-system` tasks 3.1, 5.1 and 6.1 are implemented (design D12).
